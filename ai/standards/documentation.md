# Documentation Standard

## Documentation Goals

Documentation should help future AI and human contributors understand the product, architecture, standards, prompts, and task history without guessing.

## Required Documentation Areas

- Product vision and scope.
- Engineering principles.
- AI orchestration and agent roles.
- Coding, architecture, frontend, backend, database, security, performance, testing, and git standards.
- Task files with acceptance criteria and completion notes.
- Prompt templates and schema versions when AI implementation begins.

## Writing Rules

- Be specific and concise.
- Document decisions, tradeoffs, and constraints.
- Keep task documentation close to the work.
- Update docs in the same task that changes behavior or architecture.
- Avoid stale aspirational documentation that does not match the implementation.

## Task Documentation

Every task should include:

- Objective.
- Context.
- Scope.
- Out of scope.
- Acceptance criteria.
- Verification steps.
- Completion notes.
