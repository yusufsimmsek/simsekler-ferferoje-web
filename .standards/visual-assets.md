# Visual Asset Standard

## Purpose

ArchiFlow must use premium architectural visual assets that make each module feel like a professional workspace, not a dashboard template or wireframe.

## Requirements

- Every major module screen must contain at least one large signature visual.
- Primary module visuals must be production-ready raster artwork, generated architectural renders, real document previews, CAD/PDF previews, GIS/site visualizations, 3D scenes, or interactive visualizations.
- Simple SVG icons, generic line illustrations, wireframe placeholders, empty gradient boxes, and low-detail blueprint sketches are not acceptable as final hero artwork.
- Supporting SVG or CSS graphics may be used only as secondary overlays, motion accents, masks, or interaction layers.
- Visual assets must immediately communicate the module purpose: projects, parcels, zoning, depth/Hmax, existing plans, metraj, core library, apartment mix, share allocation, reports, and files must each feel visually distinct.
- Empty, loading, success, and error states should use contextual architectural visuals instead of generic SaaS illustrations.
- Assets must be stored in the repository or otherwise documented with stable provenance; core product experience must not depend on fragile external hotlinks.
- Image sizes, formats, and rendering behavior must be reviewed for performance and responsiveness.

## Review Gate

Visual Asset Director, Principal Product Designer, Design Critic, Frontend Engineer, Performance Engineer, and Accessibility review must approve major visual-asset changes.
