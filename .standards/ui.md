# UI Standard

## Purpose

ArchiFlow UI must feel premium, architectural, calm, dense, and operational. It must not resemble a generic dashboard template.

## Requirements

- Use Turkish user-facing copy unless a task explicitly targets another locale.
- Preserve clear information hierarchy on every screen.
- Use consistent typography, spacing, color, elevation, borders, and component states.
- Avoid nested cards, decorative clutter, and marketing-style layouts for operational tools.
- Major module screens must start with a premium visual experience; data cards, charts, and tables should follow the visual context instead of replacing it.
- Do not use simple SVG placeholders, generic line art, empty gradients, or wireframe sketches as final hero artwork.
- Every primary workflow control must be functional or clearly disabled with a domain-specific reason.
- Use stable dimensions for boards, toolbars, counters, tiles, and repeated items.
- Prevent text overflow, incoherent overlap, and layout shifts across desktop and mobile.

## Review Gate

Principal Product Designer, Visual Asset Director, and Frontend Engineer must approve major UI changes. Design Critic must review high-visibility screens.
