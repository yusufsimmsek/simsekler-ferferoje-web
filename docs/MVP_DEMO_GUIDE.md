# MVP Demo Guide

## Demo Goal

Show the complete MVP loop:

```text
Prompt -> 2D rectangular floor plan -> chat edit -> PNG/PDF export
```

The demo must stay honest: generated plans are conceptual drafts only, not construction, permit, structural, legal, CAD, or BIM output.

## Demo Checklist

Before demo:

- Run `npm install` if dependencies are missing.
- Use mock mode unless testing OpenAI intentionally.
- Confirm `.env.local` has `AI_PROVIDER=mock`.
- Run `npm run test:ai` for AI fixtures.
- Open `http://localhost:3000/projects/new`.
- Keep the browser dev tools closed unless debugging storage.

During demo:

- Generate a supported residential prompt.
- Show the rendered 2D plan.
- Point out validation status and conceptual-draft disclaimer.
- Apply one chat edit.
- Export PNG or PDF.
- Show an unsupported request and the friendly scope message if useful.

## Supported Prompts

Use these for reliable demo paths:

```text
Create a compact 1+1 apartment with living room, kitchen, bathroom, and one bedroom.
```

```text
Create a 2+1 apartment with two bedrooms, living room, kitchen, bathroom, and WC.
```

```text
Create a 3+1 apartment with balcony, open kitchen, bathroom, and WC.
```

```text
Create a simple single-floor villa concept with bright rooms and a family living area.
```

Expected behavior:

- The app returns a validated conceptual `FloorPlan`.
- Layout is generated by the deterministic rectangular layout engine.
- The editor opens with the generated plan.
- Project data is stored in browser `localStorage`.

## Unsupported Prompts

Use these to demonstrate scope control:

```text
Create a BIM model in Revit.
```

```text
Make a permit-ready legal compliance plan.
```

```text
Calculate structural beams and load-bearing columns.
```

```text
Create a photorealistic 3D render.
```

```text
Design a duplex with a second floor.
```

```text
Create a small office with workstations and meeting rooms.
```

```text
Do interior design with furniture and decor.
```

Expected behavior:

- No plan is generated.
- The API returns `AI_UNSUPPORTED_REQUEST`.
- The user sees a short explanation and a supported prompt suggestion.
- Response shape remains stable.

## Ambiguous Prompt Example

```text
Make a perfect home for everyone with all rooms huge but the total area tiny.
```

Expected behavior:

- No plan is generated.
- The API returns `AI_NEEDS_CLARIFICATION`.
- The user is asked to provide a simple one-floor residential layout.

## Chat Edit Examples

Use these after a generated project is open:

```text
Make the living room larger.
```

```text
Shrink the living room.
```

```text
Enlarge the kitchen.
```

```text
Add a bathroom.
```

```text
Add a balcony.
```

```text
Remove the balcony.
```

```text
Rename Bedroom 3 to Office.
```

Expected behavior:

- Supported edits produce structured edit actions.
- The plan is revalidated before storage and rendering.
- Unsupported edits leave the previous plan unchanged.

## localStorage Recovery Demo

If browser storage is missing, corrupted, or from an unsupported schema version:

- The editor falls back to the demo plan.
- A fallback status is shown.
- Valid stored projects are preserved when possible.

This is intentional MVP behavior until database persistence is approved.
